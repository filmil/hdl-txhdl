\datasheet{LiteMaster}{An AXI-Lite host that performs one ask at a time, only the ask whose tag follows the last one it performed, and answers every other from the last answer it kept.}

\dsfacts{\code{lib/parts/src/remote/host.rs}}{\code{txhdl\_parts::remote::host::LiteMaster}}%
{\code{//docs:examples}}

\subsection*{Function}

\code{LiteMaster} takes an \code{Ask} from \code{HostLink}, a program's
read or write, performs it as an AXI-Lite host on the design's bus, and
sends a \code{HostAnswer} back. It is what lets a program on another
machine read and write this design's registers over Ethernet (issue
1931).

The tags count up by one, and \code{LiteMaster} performs only the ask
whose tag follows the last one it performed, or the first ask it is
given (issue 2019). It keeps the tag and the answer of the last
transaction it performed, and answers any other ask from them. So a
frame lost and sent again is not performed twice, as a write repeated
on a register with a side effect would do the effect twice; and a
program can send many asks without waiting for each answer. An answer
says that every ask up to its tag is done, and an answer that names an
earlier tag than the program sent says an ask was lost and where to
start again.

\subsection*{Parameters}

None. The bus is AXI-Lite of 32-bit addresses and words, a
\code{LiteHostPort<32, 32, 4>}.

\subsection*{The answer}

\begin{center}\footnotesize
\begin{tabular}{@{}lp{0.68\textwidth}@{}}
\toprule
Field & What \\
\midrule
\code{tag} & The tag of the last transaction performed: the ask's own
tag when the ask was performed. \\
\code{asked} & The tag of the ask this answers. The two differ when the
ask came out of turn: an asked tag past the one that was due says an
ask before it was lost, and one behind the last is a stale copy the
program sent again. A repeat of the last tag is answered with the two
equal. \\
\code{data} & Of the last transaction performed: the word a read read,
or for a write the number of transactions that have failed since the
design started, wrapping. \\
\code{err} & One if the last transaction performed failed. \\
\bottomrule
\end{tabular}
\end{center}

\subsection*{Behaviour}

\begin{itemize}
\item An ask is taken when nothing is on the bus and no answer is
waiting to go.
\item An ask is performed when its tag is one more than
\code{last\_tag}, counting past 255 to 0, or when \code{have\_last} says
nothing has been performed yet, so the first ask is performed whatever
its tag. Every other ask, a repeat of the last tag among them, is
answered from \code{last\_tag}, \code{last\_data} and \code{last\_err},
and not performed.
\item Every ask taken sets \code{asked}, so its answer names it.
\item A write sends its address on \code{aw} and its word and strobe on
\code{w}, each once and each when its channel has room; a read sends its
address on \code{ar}. The protection bits are zero.
\item The response is taken only once the request has gone whole, so a
bus that answers early cannot end a write whose word is still waiting.
\item A response other than \code{Okay} becomes an answer with its error
bit set, and adds one to \code{fails}. A write answers the new count of
failures in place of a word.
\item The answer goes on \code{back} when it has room, and the next ask
is taken after it.
\end{itemize}

\subsection*{Used by}

\code{HostBridge}, which joins it to \code{HostLink}; \code{ex\_hostlink};
and \code{//firesim/ax7a200b} through \code{HostBridge<5>}.

\subsection*{Limits}

One transaction at a time, and one 32-bit word per transaction. The
order is by tag alone: a program must number its asks one after
another, starting from the tag after the one the first answer names,
and an ask under any other tag is answered with the last answer and not
performed, whatever its address. Only the last answer is kept, so the
answer to an ask that was performed before the last one is lost; a
failure, of a read or a write, still shows in the count the next
performed write answers.
